# FileVault

Домашний архив фото и видео. Оригиналы лежат на диске как были сняты, сведения о файлах в PostgreSQL, смотреть их можно из браузера в домашней сети. Сервер написан на Go и ставится одним статическим бинарником.

Работает на нетбуке Samsung NP-N102S: Atom N2100, одно ядро с Hyper-Threading, 1 ГБ RAM, Debian 13. В самом приложении входа по паролю нет, порт 8080 в интернет не пробрасывается.

## Задача

Снимки уже были, класть их в облако я не хотел. Из машин, которые могут быть включены постоянно, дома остался нетбук 2012 года. Памяти гигабайт, ядро одно, хдд 360 гигабайт, батарея не держит. Под это и собирался сервис.

Оригинал при загрузке не пережимается и не поворачивается. Уменьшенная копия и дата съёмки потом пересчитываются, сам файл уже нет. Если процесс упадёт посередине загрузки или удаления, на диске не должно остаться файла без строки в базе, и строки без файла. На нетбук копируется один бинарник: миграции и страница вшиты в него. Очередь в отдельной программе, Docker и второй процесс превью в этот гигабайт не помещаются.

Уже можно завести папку, переименовать её и удалить, когда она пустая. Файл можно загрузить, открыть, скачать, переименовать, переложить в другую папку и удалить. Несколько файлов страница отправляет по очереди, каждый своим запросом.

```
браузер -> API на Go -> PostgreSQL -> каталог storage
```

## Решения

### Сервер

Бинарник собирается с `CGO_ENABLED=0` под `linux/amd64`. От glibc на Debian он не зависит, собирать можно на Mac. База подключена драйвером `pgx` через `database/sql`. Запросы написаны руками, ORM нет.

Docker стоит только там, где я пишу код. На нетбуке `dockerd` забрал бы 50-100 МБ при общей памяти в 1 ГБ. Сервис запускает systemd: он же перезапускает процесс, если тот вышел с ошибкой.

Превью считает один worker. Второе физическое ядро брать неоткуда, а Redis или другая очередь заняла бы память. Состояние очереди лежит в колонке `preview_status` таблицы `files`. После перезапуска строки `pending` на месте. Worker просыпается от канала с буфером на одно сообщение и от таймера раз в минуту. Пока он занят одним файлом, остальные ждут.

PostgreSQL ужат под этот объём памяти: `shared_buffers = 128MB`, `max_connections = 20`. Пул приложения на 10 соединений. Каждое соединение базы заводит свой процесс.

Миграции и файлы страницы вшиты через `//go:embed`. Страницу отдельно от сервера не выложить. При деплое рядом с бинарником ничего не копируется и ничего не накатывается руками.

Превью пишется в JPEG, 320 px по длинной стороне, качество 80. Нормальный кодировщик WebP в Go сидит на `libwebp` и тянет CGO. На картинке такого размера разница выходит на десятки килобайт, статическую сборку из-за этого ломать не стал.

В Debian 13 каталог `/tmp` по умолчанию лежит в памяти (`tmpfs`), размер около половины RAM. Всё, что больше 32 МБ, `ParseMultipartForm` пишет во временный файл. Большое видео туда либо не войдёт, либо вытеснит PostgreSQL. `tmp.mount` поэтому замаскирован, `/tmp` остаётся каталогом на диске.

### Папки, даты, пути

Папка хранится строкой в PostgreSQL. Каталога с её именем на диске нет: перенос файла меняет `dir_id`, байты остаются где лежали. Вложенных папок нет. Корень тоже строка, с флагом `is_root`, её вставляет первая миграция. `files.dir_id` из-за этого всегда заполнен. Второй корень запрещает частичный уникальный индекс, одной проверки в коде мало. В коде корень узнаётся по флагу, не по номеру id.

Имена папок уникальны без учёта регистра, индекс по `lower(name)`. Годится имя или нет, решает приложение. В базе для этого нет `CHECK`. Правила общие для папок и файлов. Пробелы по краям обрезаются, пустое имя не проходит, как и `.` с `..`. Длина до 255 байт. Нельзя `/ \ < > : " | ? *` и управляющие символы.

Дата снимка хранится как `TIMESTAMP` без часового пояса. EXIF записывает показания часов камеры и не пишет смещение. Зона сервера сдвинула бы время съёмки. `created_at` и `updated_at` относятся к самому серверу и хранятся с поясом. `updated_at` меняет триггер в базе. Колонка `date_source` помнит источник: `exif`, `modtime` или `upload`. Так файл, у которого известна только дата загрузки, не встаёт вперёд при сортировке по дате съёмки. EXIF сервер пока не читает. В колонке либо время, которое прислал браузер, либо время загрузки. Файл на диске полный, дату можно проставить отдельным проходом.

`description` хранится пустой строкой. Отсутствующее описание и пустое здесь одно и то же, а `NULL` в модели потянул бы `sql.NullString`. `NULL` оставлен у `preview_path`: превью появляется позже. Размер файла в Go это `int64`, в базе `BIGINT`. От разрядности `int` размер не зависит.

Файл на диске лежит так:

```
original/ГГГГ/ММ/ДД/ab/0123456789abcdef.jpg
```

`ab` берётся из первых двух символов SHA-256 содержимого. Каталогов выходит 256. В путь попадает дата загрузки. Архив заливается за раз, и без этого уровня почти всё оказалось бы в одном каталоге. Хеш и так считается при записи, одним проходом вместе с копированием на диск (`io.MultiWriter`). Отдельного чтения файла шардинг не добавляет. Одного символа мало, в каталоге останутся сотни файлов. Три символа дают 4096 каталогов, на таком объёме многие будут пустыми.

Имя файла случайное: из `crypto/rand`, в hex, плюс расширение оригинала в нижнем регистре. Назвать файл самим хешем нельзя. Одинаковые файлы хранить разрешено, а `storage_path` уникален, и двум одинаковым файлам достался бы один путь. Имя, под которым файл пришёл от пользователя, лежит в `original_name`.

В базе путь относительный, от каталога `STORAGE_DIR`. Абсолютный путь сломается при переносе архива на другой диск. `filepath.IsLocal` не пропускает путь выше корня хранилища. Клиенту путь не отдаётся, файл запрашивается по id.

Конечный путь неизвестен, пока не посчитан хеш. Поэтому запись идёт в `storage/tmp`, а потом `os.Rename`. Переименование атомарно только внутри одной файловой системы, так что временный каталог лежит в `STORAGE_DIR`, рядом с `original`. Недописанный файл в `original` не появляется. На ext4 открытие по готовому пути от размера каталога уже почти не страдает. Два символа хеша нужны листингу, `rsync` и бэкапу. Раскладку можно поменять позже: разложить файлы заново и обновить `storage_path`. К API это отношения не имеет.

Порядок имён в списке папок зависит от локали кластера PostgreSQL. В разработке и на нетбуке это `en_US.utf8`. Локаль задаётся при создании кластера, обычной настройкой потом не меняется.

```sql
SELECT datcollate FROM pg_database WHERE datname = current_database();
```

`SHOW lc_collate` начиная с PostgreSQL 16 убран.

### Загрузка и удаление

Общей транзакции у PostgreSQL и файловой системы нет.

Один запрос несёт один файл. Сначала запись на диск, потом `INSERT`. Диск не принял файл, в базу ничего не добавляется. `INSERT` не прошёл, файл с диска удаляется. Если не удалился и он, обе ошибки возвращаются вместе, через `errors.Join`. Пачку страница шлёт циклом из таких запросов. Сбой одного остальные не отменяет. Папка из URL проверяется до записи файла.

Рядом с файлом приходит JSON:

```json
{"modtime": "2023-08-28T14:32:10", "description": "подпись"}
```

`modtime` записан местным временем, без зоны. Браузер собирает строку из года, месяца, дня и времени. `toISOString()` отдаёт UTC, для этой колонки такая строка не годится. Поля нет или оно не разобралось: остаётся время загрузки и `date_source = upload`. JSON, который не парсится, даёт ответ 400. Тип файла берётся из первых 512 байт, `http.DetectContentType`. Расширение и заголовок от браузера не используются. Размер режет `MAX_UPLOAD_BYTES` через `http.MaxBytesReader`.

Удаление сначала переносит оригинал в `trash`. Потом удаляется строка. После удачного `DELETE` файл стирается из `trash`. Если `DELETE` не прошёл, оригинал возвращается на старое место. Сбой переноса превью и ошибка окончательной очистки пишутся в лог. Если процесс умрёт после переноса и до `DELETE`, файл останется в `trash`. При старте этот каталог пока не разбирается.

Удалить можно только пустую папку. У файлов стоит `ON DELETE RESTRICT`. Каскадное удаление стёрло бы строки и оставило файлы на диске без записи в базе. Отказ базы приходит с кодом `23503` и превращается в ответ 409. Считать файлы отдельным запросом перед удалением незачем: запрос и параллельная загрузка разошлись бы по времени. Корень не удаляется и не переименовывается.

При загрузке можно положить два одинаковых файла и два файла с одним именем. При переименовании и переносе имя внутри папки свободно, сравнение без учёта регистра, проверяет приложение. Два таких запроса в один момент могут оба пройти. Индекс по папке и имени поставлю вместе с запретом повторов на загрузке, когда уже залитые дубли будут убраны.

### Превью

Ответ об успешной загрузке не ждёт картинку. Ориентация из EXIF применяется к пикселям превью. В готовом JPEG этого тега уже нет, картинка должна быть повёрнута сама. Оригинал не трогается. До декода читается заголовок, картинка больше 50 мегапикселей отбрасывается. Вокруг декода стоит `recover`: битый файл не роняет процесс. Ошибка превью записывает статус `failed`. Видео, HEIC и PDF получают `skipped`, на карточке рисуется заглушка. Превью видео, когда до него дойдёт, будет снимать внешняя программа через `os/exec`, с таймаутом. CGO для этого не нужен.

### Страница и API

Страница одна: HTML, CSS, jQuery. Запросы идут через `fetch`. Сборщика нет, файлы страницы вшиты в бинарник. Имена из базы вставляются текстом. В имени может быть знак `<`. Список папок сортирует SQL, `ORDER BY name`. Вторая сортировка на странице развела бы порядок с сервером.

Успешный ответ приходит JSON-ом, без обёртки и без поля `ok`. Ошибка приходит текстом, страница смотрит на статус. `id` меньше 1 или не число даёт 400 до обращения к базе. В ответе о файле нет `storage_path`, `preview_path`, `sha256`, `dir_id`. Оригинал отдаёт `http.ServeContent`: для видео работает `Range`, файл целиком в память не читается, `Content-Type` берётся из базы. Файл с типом `text/html` всегда скачивается.

| Метод и путь | Что делает |
|---|---|
| `GET /api/dirs` | папки, включая корень, и число файлов в каждой |
| `POST /api/dirs` | создать папку |
| `POST /api/dirs/{id}/rename` | переименовать папку |
| `DELETE /api/dirs/{id}` | удалить пустую папку |
| `GET /api/dirs/{id}/files` | файлы папки |
| `POST /api/dirs/{id}/files` | загрузить один файл |
| `GET /api/dirs/{id}/count_files` | число файлов |
| `GET /api/files/{id}/original` | оригинал, с `?download=1` скачивание |
| `GET /api/files/{id}/preview` | превью JPEG |
| `POST /api/files/{id}/rename` | переименовать файл, расширение остаётся |
| `POST /api/files/{id}/move` | перенести в другую папку |
| `DELETE /api/files/{id}` | удалить файл |

## Разработка

Нужны Go 1.25 и Docker.

```bash
cp .env.example .env
docker compose up -d
curl -s http://localhost:8080/api/dirs
```

В `.env`:

- `DB_HOST=filestorage_db`, имя сервиса в compose
- `DB_NAME=filestorage`
- `DB_USER=filestorage_user`
- `DB_PASSWORD`, любой локальный
- `STORAGE_DIR=/app/storage`
- `MAX_UPLOAD_BYTES` обязателен, в коде нет запасного значения. В примере 1 ГБ

`DATABASE_URL` можно оставить с `${DB_USER}` и остальными подстановками, compose их раскрывает. Этот адрес работает внутри сети compose. С хоста база открыта на `localhost` и порту `DB_HOST_PORT`. В примере порт 5433.

В `docker-compose.yml` сейчас образ `postgres:15`. На нетбуке PostgreSQL 17 из Debian. Мажор лучше держать одним: 17 не читает каталог данных 15-й версии, смена образа означает новый том.

```bash
make test            # без базы
make test-db-create  # один раз, пустая база filevault_test
make test-int        # тесты на настоящем PostgreSQL
```

Команды `make` запускаются на хосте, не в контейнере `app`. `DATABASE_URL` из `.env` с хоста не открывается: там имя контейнера.

## SSH

Нетбук сидит в домашней сети, адрес ему выдаёт роутер. Сейчас это `192.168.31.88`. Ключ для него отдельный.

На Mac:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_netbook -C "filevault-netbook"
```

В `~/.ssh/config`:

```
Host netbook
  HostName 192.168.31.88
  User serjio
  IdentityFile ~/.ssh/id_ed25519_netbook
  IdentitiesOnly yes
  AddKeysToAgent yes
  UseKeychain yes
```

`IdentitiesOnly` оставляет ssh только этот ключ, без перебора остальных. Пользователь `serjio` создаётся при установке Debian и может вызывать `sudo`. При установке системы нужен пакет OpenSSH server и локаль `en_US.UTF-8`: от неё потом возьмётся локаль PostgreSQL.

Когда нетбук включён и виден в сети:

```bash
ssh-copy-id -i ~/.ssh/id_ed25519_netbook serjio@192.168.31.88
ssh netbook
```

`./deploy.sh` ходит на имя `netbook` из этого файла. Другой адрес передаётся так:

```bash
DEPLOY_HOST=serjio@192.168.31.88 ./deploy.sh
```

Если адрес сменился, правится `HostName`. После переустановки системы у нетбука новый ключ хоста, и ssh откажется подключаться. Старую запись надо убрать и зайти ещё раз:

```bash
ssh-keygen -R 192.168.31.88
ssh netbook
```

Адрес стоит закрепить в роутере. Иначе после перезагрузки DHCP `HostName` снова устареет.

## Установка на нетбук

Пароль базы генерируется на нетбуке и живёт только в `/etc/filevault/env`:

```bash
openssl rand -hex 16
```

Закрытая крышка не должна усыплять машину. В `/etc/systemd/logind.conf`:

```ini
HandleLidSwitch=ignore
HandleLidSwitchExternalPower=ignore
```

```bash
sudo systemctl restart systemd-logind
sudo systemctl mask tmp.mount
sudo reboot
```

После перезагрузки `findmnt /tmp` ничего не печатает: `/tmp` на диске.

```bash
sudo apt install postgresql
sudo -u postgres psql -c "SELECT datcollate FROM pg_database WHERE datname = 'postgres';"
```

В ответе нужно `en_US.UTF-8`. Если кластер только создан, данных в нём нет, а локаль другая:

```bash
sudo dpkg-reconfigure locales
sudo pg_dropcluster 17 main --stop
sudo pg_createcluster 17 main --locale=en_US.UTF-8 --start
```

Дальше пользователь и база. Пароль спросит `createuser`.

```bash
sudo -u postgres createuser --pwprompt filevault
sudo -u postgres createdb -O filevault filevault
```

Файл `/etc/postgresql/17/main/conf.d/filevault.conf`. Каталог `conf.d` Debian подключает сам:

```ini
shared_buffers = 128MB
effective_cache_size = 512MB
work_mem = 4MB
maintenance_work_mem = 64MB
max_connections = 20
```

```bash
sudo systemctl restart postgresql
sudo -u postgres psql -c 'SHOW shared_buffers;' -c 'SHOW effective_cache_size;'
```

Ожидаются `128MB` и `512MB`. База слушает только `localhost`, приложение на той же машине.

```bash
sudo useradd --system --home /var/lib/filevault --shell /usr/sbin/nologin filevault
sudo mkdir -p /opt/filevault /etc/filevault /var/lib/filevault/storage
sudo chown -R filevault:filevault /var/lib/filevault
```

| Путь | Что там |
|---|---|
| `/opt/filevault/filevault` | бинарник |
| `/etc/filevault/env` | настройки, внутри пароль базы |
| `/var/lib/filevault/storage` | файлы архива, каталог `STORAGE_DIR` |

`/etc/filevault/env`. systemd подстановки `${...}` не раскрывает, строка подключения пишется целиком. Лимит загрузки на сервере 4 ГБ. В разработке в `.env` стоит 1 ГБ.

```ini
APP_PORT=8080
DATABASE_URL=postgres://filevault:ПАРОЛЬ@localhost:5432/filevault?sslmode=disable&application_name=filevault
STORAGE_DIR=/var/lib/filevault/storage
MAX_UPLOAD_BYTES=4294967296
```

```bash
sudo chown root:filevault /etc/filevault/env
sudo chmod 640 /etc/filevault/env
```

Юнит `/etc/systemd/system/filevault.service`:

```ini
[Unit]
Description=FileVault
After=network-online.target postgresql.service
Wants=network-online.target
Requires=postgresql.service

[Service]
User=filevault
Group=filevault
EnvironmentFile=/etc/filevault/env
ExecStart=/opt/filevault/filevault
Restart=always
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/filevault
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

`PrivateTmp` даёт сервису свой каталог внутри `/tmp`. После маскировки `tmp.mount` этот каталог тоже на диске. `Restart=always` срабатывает, потому что при неудачном старте программа выходит через `log.Fatal` и код возврата ненулевой.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now filevault
journalctl -u filevault -f
```

Журнал сервиса виден root и группе `adm`. Без неё `journalctl` покажет пусто. Один раз: `sudo usermod -aG adm $USER`, потом войти заново.

Миграции и корневая папка создаются на первом старте. Следующие обновления с Mac, из каталога проекта:

```bash
./deploy.sh
```

Скрипт смотрит, закоммичены ли изменения в `cmd`, `internal`, `web`, `go.mod` и `go.sum`. Если нет, останавливается. `FORCE=1 ./deploy.sh` заливает рабочую копию как есть. Дальше идут `go vet`, `go test`, сборка `linux/amd64`, копирование по SSH и `systemctl restart`. `sudo` на нетбуке один раз спрашивает пароль.

Проверка на нетбуке: `wget -qO- localhost:8080/api/dirs`. С Mac страница открывается по адресу `http://192.168.31.88:8080`.
